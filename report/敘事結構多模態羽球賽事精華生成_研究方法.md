# 打造具敘事結構之多模態羽球賽事精華生成

### **二、 研究方法**

本研究的核心目標，是將結構化的羽球逐拍賽事資料，自動轉化為一段具有完整敘事張力、可直接發布於 Instagram Reels／YouTube Shorts 的精華短片。為達成此目標，我們設計了一條涵蓋「資料解析 → 精華選取 → 敘事編排 → Multi-Agent 腳本生成 → 多模態合成 → 系統整合」的端到端架構。其中，本子計畫的三項核心創新分別為：**（一）以敘事弧線為核心的精華結構編排**、**（二）Writer–Critic–Audience Multi-Agent 品質迴圈之腳本生成**，以及 **（三）語音、虛擬主播與影片三模態協同之自動合成 ** 。以下分項說明。

#### **2.1 系統總覽與端到端架構**

傳統的賽事精華製作，需仰賴專業剪輯人員與旁白撰稿，耗時且難以規模化；而既有的自動化方法多半止於「選出精彩片段並拼接」，缺乏完整的故事線與口語旁白，成品往往像片段集錦而非一則可看完的短影音。為此，本子計畫提出一套完整的生成流程，使系統不僅能挑選精華，更能**像一位新聞主播般，把比賽說成一個有起承轉合的故事**。

整體流程依序為：先由資料載入模組取得逐拍標註與預剪回合影片；接著由賽事分析模組以**規則式的興奮度評分**挑出 5–8 個精華回合，並指派敘事角色；隨後進入由大型語言模型（LLM）驅動的 Multi-Agent 迴圈，生成並反覆修訂中文旁白腳本；最後依序進行語音合成、虛擬主播生成與影片合成，輸出最終短片。

#### **2.2 結構化賽事資料解析與精華片段選取**

本子計畫以 ShuttleSet 的逐拍標註資料為基礎，每場比賽包含回合分段表（RallySeg）、各局逐拍標註（label）以及預先切好的回合影片。逐拍標註提供了每一拍的球種、擊球與落點區域、得失分原因等三十餘個欄位，是後續評分與旁白生成的事實依據。

**規則式興奮度評分。** 我們設計了一個可解釋的啟發式評分函數，從四個面向衡量每個回合的精彩程度，並以加權方式合成：

* **回合長度（權重 30%）**：以拍數反映來回的精彩程度，計為 `min(拍數 ÷ 25 × 100, 100)`。
* **致勝方式（權重 20%）**：主動「落地致勝」給 80 分，因對手掛網、出界、未過網等被動失誤得分給 40 分，其餘為 0 分。
* **技術難度（權重 20%）**：統計回合中的高難度擊球（殺球、撲球、點扣）、繞頭擊球（around-the-head）以及反拍進攻等事件，每項計分後以 `min(技術次數 × 15, 100)` 計算。
* **比分情境（權重 30%）**：依當下比分的張力給分——接近賽末且比分膠著（最高分 ≥ 20 且分差 ≤ 1）給最高的 100 分，19 分以上的拉鋸給 80 分，中段相持依序遞減，比賽前段或大比分差則給最低的 20 分。


**選取策略。** 系統依興奮度分數由高至低選取至多 N 個回合，並輔以**各局多樣性保證**：若某一局在前述選取後完全沒有回合入選，則補入該局分數最高的回合，避免精華過度集中於單一局而失去整場比賽的代表性。


目前四因子權重為人工設定；未來在累積足量「精華／非精華」人工標註後，可改以 learning-to-rank 等可學習權重取代固定權重。

#### **2.3 敘事結構編排：五幕弧線與十段新聞播報結構**

羽球賽事的精彩程度並非均勻分布，若僅將高興奮度回合依序拼接，往往缺乏起承轉合而難以維繫觀眾注意力。為此，本研究設計了一套**以規則為基礎**的敘事編排機制，將選取出的精華回合對應到一條五幕式敘事弧線，再嵌入固定的新聞播報腳本骨架，使成品兼具資訊密度與戲劇張力。

**五幕敘事弧線。** 系統首先在所有入選回合中取**興奮度最高者作為「開場（hook）」並前置於影片開頭**（倒敘手法），以在前三秒抓住觀眾；其餘回合則依其在賽事中的**原始時間順序**，按比例切分為四個敘事階段：前 30% 為「鋪陳（buildup）」、30%–70% 為「轉折（turning point）」、70%–90% 為「高潮（climax）」，其餘為「收尾（ending）」。

**十段新聞播報結構。** 在敘事弧線之上，撰稿 Agent（詳見 2.4）會將內容組織為一個固定的十段式新聞播報腳本：①開場 → ②主播開場白→ ③賽事背景介紹 → ④–⑧五段關鍵回合解析 → ⑨賽事總結 → ⑩主播收尾。

#### **2.4 Multi-Agent 協作之腳本生成與品質迴圈**

旁白腳本的品質直接決定成品的可看性，但單次呼叫 LLM 生成的腳本，往往在節奏、事實準確性與娛樂性之間難以兼顧。為此，本研究提出一套基於 LangGraph 狀態圖（StateGraph）的**生成–評估–再生成（Generate–Evaluate–ReGenerate, G-E-RG）Multi-Agent 迴圈**，透過「撰稿、評論、觀眾」三個智能體的協作與反覆修訂，逐步提升腳本品質。

**整體流程。** 狀態圖的節點依序為 撰稿（Writer）→ 評論（Critic）→ 觀眾（Audience）→ 品質門檻（Quality Gate），並在品質門檻後以條件分支決定「結束」或「迴圈回撰稿節點再修訂」。

**撰稿 Agent（Writer）。** 負責生成與修訂中文旁白腳本，並在文字中內嵌 Fish Speech 情緒標籤（如 `[excited]`、`[whispering]`），這些標籤同時作為**文字與語音韻律之間的橋接**，於後續合成階段直接驅動語音情緒。

**評論 Agent（Critic）。** 模擬評論家，從五個維度為腳本評分（各 0–10 分），並以加權方式計算總分：節奏（25%）、準確性（20%）、情緒弧線（20%）、娛樂性（20%）、時長（15%），以確保符合系統設計與使用者需求。

**觀眾 Agent（Audience）。** 以四個 **LLM 模擬人物**——路人觀眾、羽球愛好者、短影音重度用戶、體育主播——分別預測其觀看完成率（watch-through）、互動意願（engagement，0–10）與分享意願（would share），並聚合為平均完成率、平均互動分數與分享率。

**品質門檻（Quality Gate）。** 採固定門檻規則：當評論總分 ≥ 7.0、平均完成率 ≥ 70%、平均互動分數 ≥ 6.0 三項條件**同時成立**時通過，否則將評論與觀眾的具體回饋連同前一版腳本一併回送撰稿 Agent 進行修訂。

#### **2.5 多模態合成：情緒語音、虛擬主播與影片合成**

腳本完成後，系統進入多模態合成階段，將純文字旁白轉化為包含**語音、虛擬主播與字幕**的完整影片。

**情緒語音合成。** 採用 Fish Speech 雲端服務，逐段合成旁白語音，並將腳本中內嵌的情緒標籤原樣透傳，使語音得以呈現對應的情緒起伏。

**虛擬主播生成。** 系統將語音連同主播參考照片，傳送至 EchoMimicV3 talking-head 服務，算出對嘴的主播影像（128p）。

**字幕與影片合成。** 由影片合成模組統整所有模態。系統先生成字幕，再依每段的 `rally_id`（比分字串，如 `1_05_04`）對應到該回合的影片片段。


目前虛擬主播採用固定的參考影像與通用語音；未來可導入自定義語音複製與指定主播肖像，讓使用者可以選擇喜歡的主播。
