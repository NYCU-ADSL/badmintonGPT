# data-analysis playbook (calculate before charting)

For any data question requiring calculation, the sequence is fixed: **fetch data → calculate with Python → present**.
Do not skip the Python calculation step or calculate mentally or guess numbers.

## Environment (know this first)

- The container has `python3` (3.12). exec runs in a **bwrap sandbox restricted to the workspace**.
- Available: Python **standard library**—
  `statistics` (mean / median / mode / pstdev / stdev / quantiles / correlation /
  linear_regression), `collections` (Counter / defaultdict), `math`, `itertools`,
  `json`, `csv`.
- **Unavailable**: `pandas` / `numpy` / `matplotlib` / `scipy` (not installed). **Do not import them or
  run `pip install`**—installation fails in the sandbox and only wastes turns. The standard library suffices for ordinary badminton statistics.
- exec **cannot access the database** (sandbox restrictions, and access should go through MCP anyway). Always fetch data through badminton-db MCP first.

## Procedure

1. **Fetch**: follow the **badminton-db** skill and use MCP `query` to retrieve rows (a single SELECT;
   always include a `match_name` filter for a specific match).
2. **Calculate**: use `exec` to **run `python3 -c "..."` directly**, embedding the previous rows as a Python literal—
   **do not write a .py file with `write_file` first, or use echo/heredoc**. Use only the standard library.
   - Wrap the outer command in single quotes: `python3 -c '...'`; use **double quotes** `"..."` for
     all strings inside Python to avoid conflicts (Chinese enums contain no single quotes, so they are safe).
   - Only **`print` compact results** (JSON or a small table), not raw data (exec output above 10,000 characters is truncated).
3. **Present**: use the numbers calculated by Python—
   - For charts → follow the **visualise** skill and wrap the result in a visualizer code fence (Chart.js / SVG,
     **not** a PNG generated by matplotlib).
   - For tables → output a Markdown table directly.

## Strict rules

- **Run `python3 -c` directly; do not write files**. **Always calculate numbers with Python**; every statistic
  in the response must match the script's printed results.
- Always create charts with the **visualise** skill (HTML / SVG embedded in the conversation); **do not** generate
  image files with Python (the container has no matplotlib, and charts must embed in the WebUI).
- Use the standard library; if pandas / numpy are truly needed, install them in the image instead (tell the user), not through exec.

## Example: a player's shot-type proportions → bar chart

1. Fetch data with MCP (badminton-db):
   ```sql
   SELECT type, COUNT(*) n FROM shots
   WHERE match_name='<matches.name>' AND player='A' GROUP BY type ORDER BY n DESC;
   ```
2. Embed the returned rows and run directly with `exec` (command value below):
   ```bash
   python3 -c '
   import json
   rows = [{"type": "殺球", "n": 42}, {"type": "挑球", "n": 31}]  # ← rows returned by MCP
   total = sum(r["n"] for r in rows)
   dist = [{"type": r["type"], "n": r["n"], "pct": round(100 * r["n"] / total, 1)} for r in rows]
   print(json.dumps({"total": total, "dist": dist}, ensure_ascii=False))
   '
   ```
3. Use `dist` containing `pct` → draw a bar chart per the **visualise** skill or output a Markdown table.

## Example: shots per rally (descriptive statistics)

```bash
python3 -c '
import json, statistics as st
spr = [12, 8, 21, 5, 33, 9]  # ← embed the shots-per-rally values queried through MCP
print(json.dumps({
    "n_rallies": len(spr),
    "mean": round(st.mean(spr), 1),
    "median": st.median(spr),
    "max": max(spr),
    "p90": round(st.quantiles(spr, n=10)[-1], 1),
}, ensure_ascii=False))
'
```
Once results are available, draw a histogram (visualise skill) or output a table as needed.
